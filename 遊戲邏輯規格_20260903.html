1狀態機（房間 phase）

// 房間生命週期
LOBBY ──startGame──▶ ROLE_ASSIGN ──▶ ROUND_LOOP ──(下班/全滅)──▶ ENDED ──restart──▶ LOBBY

// ROUND_LOOP 內每回合的子階段（依序）
SCENE      // 翻場景卡，套用本回合修正（公開）
ADMIN      // 老闆行政：派任務、（可）發升職令指派主管
CHOOSE     // 全員同時暗選（員工:躲哪+出牌；老闆:巡哪；主管:協查）

REVEAL     // 公開結果；房主按「下一回合」或計時自動 → 回 SCENE
同步點：CHOOSE 是關鍵。伺服器偵測「所有存活員工 + 老闆 (+主管) 都已提交」→ 自動進 RESOLVE。加每階段計時器（預設 CHOOSE 45 秒）：逾時者套用預設動作（員工＝待辦公室、老闆＝不巡、主管＝不協查），避免有人掛機卡住全場。

3每回合精確流程

  1. SCENE：翻一張場景卡，設 room.scene，套用其本回合修正（見 §6.4）。廣播。
  2. ADMIN（老闆）：(a) 對沒有任務的員工派任務（從 taskDeck 抽，指定對象）；(b) 若 promoteCooldown==0 可發升職令指派主管，被指定者選接受/拒絕。設定完老闆按「進入本回合」。
  3. CHOOSE（同時暗選）：
    • 員工：選 zone ＋ action（摸魚 / 認真工作 / 待命）＋可預備一張手牌（藉口留到被抓時、道具即時）。
    • 老闆：選 bossInspect 個 zone（受連查限制）＋可出一張老闆技。
    • 主管：選是否協查、協查哪區。
    全提交或逾時 → RESOLVE。
  4. RESOLVE：跑 §5 演算法。
  5. REVEAL：廣播結果；檢查勝負；房主續行或計時自動。

5結算演算法（順序至關重要）

為何順序重要：桌遊靠人腦「同時」處理；程式必須定死先後，否則同一張藉口卡、同一次協查會算兩次或漏算。以下為權威順序。
function resolveRound(room):
  emps = 存活員工
  // 5.1 先蒐集本回合各區的「巡查來源」
  inspected = set(老闆bossZones) ∪ (主管協查區 if 有)
  // 幽靈行動先套用（可能改變 inspected：少巡一區/打斷協查）
  applyGhostActions(room, inspected)

  // 5.2 逐員工判定（不即時扣心悸，先記帳到 pendingAnxiety）
  for e in emps:
    z = e.zone (預設 office)
    if e.action == 認真工作:
        e 安全；若有任務 progress += 2；gain=0
    elif z == office:
        安全；gain=0；officePeople++
    else (摸魚/邊做邊摸):
        caught = (z in inspected) 或 (菜鳥 且 相鄰(z) in inspected)
        if caught:
            // 藉口卡 > 免死 > 主管協查專屬(005場景無效藉口) 的優先序
            if 玩家出藉口卡 且 場景允許: 擋下，處理藉口效果
            elif 老鳥 且 immunity>0: immunity--; 擋下
            else: e.caught=true; pendingAnxiety[e] += (菜鳥?3:2); gain=0
                  if 有任務: 任務凍結(overdue)
        if not caught:
            gain = max(0, z.slack + (老鳥?-1:+1) + 場景加成)
            e.slackCount++; e.points += gain; pendingAnxiety[e] += z.anxiety
            if 有任務(邊做邊摸): progress += 1
    e.lastZone = z

  // 5.3 任務完成/逾期
  for e with task:
    if task.progress >= task.need: task.done; e.points+=1(交差獎勵)
    elif task.deadlineLeft-1 <= 0:
        if task.state!='graceUsed': task.state='graceUsed'(給一次補交)   // v2.1
        else: 標記可資遣(老闆需棄一張技能卡才能執行)

  // 5.4 同儕壓力（辦公室）→ 併入 pendingAnxiety
  for e in emps: pendingAnxiety[e] += (officePeople - (e在office?1:0))

  // 5.5 回合末一次結算心悸 + 出局判定  // v2.1 關鍵
  for e in emps:
    e.anxiety += pendingAnxiety[e]
    if e.anxiety >= ANXIETY_OUT(4, 6人局3): eliminate(e) → isGhost=true

  // 5.6 主管任期 / 升職冷卻遞減
  tickSupervisor(room); promoteCooldown = max(0, promoteCooldown-1)

  buildReveal(); checkWin()

6各機制細節

6.1 職級（老鳥/菜鳥）

  • 菜鳥：摸魚 gain +1；相鄰區被巡也算被抓；被抓 pendingAnxiety +3；起手手牌 -1。
  • 老鳥：摸魚 gain -1；immunity=1（自動擋第一次被抓/資遣）；連兩回合被同區盯上才真的抓到（需追蹤 bossLockOn[empId]=streak）；每 2 回可「罩學弟」。
  • 相鄰定義：座位-影印-茶水-廁所-頂樓 線性，首尾不相鄰。

6.2 任務系統（核心新增）

員工動作任務進度偷懶風險
認真工作+20安全
邊做邊摸（去摸魚區且身上有任務）+1照常被巡到=抓怠工、任務凍結
擺爛（去摸魚區但不理任務）+0照常易逾期→補交→資遣

實作：action='work'→純推進；action='slack'且有task→邊做邊摸(+1)；action='slack'視為想賺分，是否推進任務由「是否在任務允許區」判定或簡化為一律+1。資遣採兩段：先 graceUsed，再需老闆棄技能卡。

6.3 升職陷阱（主管）

  • 老闆 ADMIN 階段、promoteCooldown==0 時可指派；被指定者接受→supervisorId、supervisorTermLeft=2、promoteCooldown=3；拒絕→該員 anxiety+1 且該回合強制認真。
  • 主管在任：不能出摸魚；免疫被抓；CHOOSE 可選協查區，協查中該區摸魚員工→出局，主管 points+2。
  • tickSupervisor：每回 supervisorTermLeft--，歸零卸任。

6.4 場景卡（程式化效果）

每張場景卡是一組「本回合修正旗標」。實作成 applyScene(room, scene) 設定 flags，結算時讀取：

場景程式效果（本回合 flag）
晨會中bossCannotInspect=true；slackBonus=+1
稽核日bossInspect+=1；allAnxiety+=1；taskNeed+=1
老闆外出bossMode='remote'（指定1人猜區才抓）；cannotAssignTask=true
死線降臨settleOverdueNow=true
突襲的老闆召喚(005)excuseDisabled=true；被抓即出局
團購手搖全員 points+2；nextRoundLockZone='office'
發薪日全員 anxiety-1

6.5 藉口/道具卡

  • 藉口卡：CHOOSE 時「備牌」，RESOLVE 判定被抓時自動嘗試觸發（除非 excuseDisabled）。
  • 道具卡（通風報信=看老闆巡哪、影印機卡紙=老闆少巡一區…）：多為即時效果，於 CHOOSE 提交時或 RESOLVE 早期套用。
  • MVP 可先不做手牌，用「認真/摸魚」二選一；Phase 4 再加牌庫與抽補。

6.6 幽靈

出局→isGhost=true, alive=false。每回 CHOOSE 可出一張幽靈行動：報信（把老闆巡區私訊給一名員工）/ 騷擾（ghostReduceInspect 少巡一區 / 打斷協查 / 使一張老闆技失效）。於 5.1 applyGhostActions 套用。

7勝負判定

function checkWin(room):
  aliveEmps = 存活員工
  // 1) 全滅 → 老闆完勝
  if aliveEmps.length == 0: end('boss','所有員工出局'); return
  if round >= rounds:                      // 下班
    // 2) 任務完成率達門檻 → 老闆業績勝
    rate = doneTasks / issuedTasks
    if rate >= threshold(標準0.7, 可調0.6~0.8): end('boss', '業績達標'); return
    // 3) 否則員工陣營守住 → 摸魚王
    winner = max slackCount among aliveEmps (tie: 心悸少者)
    end('emp', '摸魚王='+winner.name, winner.id)

MVP 目前只有「摸魚次數過半」單一條件；Phase 2 導入任務後改為此三方矩陣。

8邊緣情況與同步

  • 全提交偵測：每次 submit 後檢查存活員工 + 老闆 (+主管) 是否到齊 → 觸發 RESOLVE。
  • 逾時預設：CHOOSE 計時器到 → 未提交者套預設（員工=辦公室、老闆=不巡、主管=不協查）。
  • 斷線：標 connected=false；其選擇用預設；重連以同名或 token 恢復（MVP 用 socket.id，Phase 5 改持久 token）。
  • 房主離線：移交給下一位在線者（已實作）。
  • 平手：摸魚次數同→比心悸少；再同→並列。
  • 老闆也斷線：暫停回合或指派代理；MVP 先暫停等重連。

建議先做 Phase 2：任務系統是「進階版靈魂」的第一塊，也是把 MVP 從「純躲貓貓」變成「邊做邊摸」的關鍵。加完就有明顯的深度提升，且不需要牌庫/UI 大改。

10要你拍板的設計問題

Q1 回合節奏：CHOOSE 要不要加倒數計時器（防掛機）？預設幾秒？（建議 45 秒，逾時套預設）

Q2 主管協查殺傷力：協查抓到直接出局，會不會太強？可改為「該次不算+心悸+2」與一般被抓一致。

Q3 藉口卡：Phase 4 才做手牌；在那之前老鳥免死是唯一防禦，可否接受？

Q4 完成率門檻：線上預設用七成（0.7）？還是開房時讓房主選六～八成？
